# 行程结果 Dashboard v2 设计

日期：2026-07-29

## 背景

当前 Dashboard 能编辑价格和重算总价，但页面仍以原始条目表为中心。它把“目标航线/占位假设”和“实际查到的候选”混在一起，导致用户无法判断每天到底怎么飞、是否直飞、几点到达、以及某个日期方案是否真实可行。

v2 的核心改造是：先呈现实际搜索到的具体候选，再由候选推导行程日和结论。没有实际查到的信息，不允许包装成结论。

## 目标

构建一个中文行程结果工作台，用于回答：

1. 每一天具体怎么走：几点到几点、从哪个城市到哪个城市、是否中转。
2. 每段航班是否直飞；如果没有直飞，明确写“未找到直飞”并展示中转候选。
3. 当前推荐的航班/酒店/项目组合为什么更好。
4. 9/29 出发与 9/30 出发等情景切换后，行程、酒店晚数、价格和总耗时如何变化。
5. 哪些内容已经实际查到，哪些仍待查，不再使用看似确定的 placeholder。

## 非目标

- 不把未搜索到的航班写成“target”“direct or one-stop target”并计入最终结论。
- 不自动下单或替用户提交 OTA 表单。
- 不保证长期价格有效；页面必须显示查询时间和来源。
- 不隐藏机场代码，但机场代码只能作为辅助信息，不能作为主要阅读文本。

## 数据原则

### 无占位结论规则

结论区、行程轴和候选卡只能使用实际搜索到的结果：

- 有具体出发时间、到达时间、价格和来源，才能作为候选。
- 没有查到直飞时，显示“未找到直飞”，不能写“直飞或中转目标”。
- 没有具体航班时，显示“待查询”，且不参与推荐评分。
- 不确定托运行李、退改、餐食时，必须作为风险标记显示。

### 航班候选字段

每个航班候选应包含：

- `id`
- `scenario_ids`
- `route_key`
- `date`
- `from_city_zh`
- `to_city_zh`
- `origin_airport_zh`
- `origin_airport_code`
- `destination_airport_zh`
- `destination_airport_code`
- `departure_time_local`
- `arrival_time_local`
- `arrival_date_offset`
- `airline_zh`
- `flight_numbers`
- `is_direct`
- `stops_count`
- `stopover_summary_zh`
- `duration_minutes`
- `price_cny`
- `checked_baggage_included`
- `source_platform`
- `source_url`
- `searched_at`
- `confidence_level`
- `notes_zh`

### 情景字段

情景用于比较不同出发/返回设定，例如：

- `S3_HRG_DEP0929`
- `S3_SSH_DEP0929`
- `S3_HRG_DEP0930`
- `S3_SSH_DEP0930`

每个情景包含：

- 出发日：9/29 或 9/30。
- 返回约束：10/6 离开埃及，10/7 前到北京。
- 埃及分支：赫尔格达或沙姆沙伊赫。
- 被选中的航班、酒店、活动、地面交通候选 id。
- 是否可行：所有必需段都有实际候选才可行。

## 页面结构

### 1. 顶部结论栏

显示：

- 当前推荐情景。
- 总价、人均、总移动时间。
- 价格分、时间分、综合分。
- 结论句，例如：“推荐 9/29 出发 + 沙姆沙伊赫，因为比赫尔格达少 ¥2,733，移动时间少 3.6 小时；代价是少卢克索历史段。”
- 数据完整性提示，例如：“10/6 开罗回北京未找到直飞，当前计入 1 次中转候选。”

### 2. 情景切换栏

提供清晰按钮：

- 9/29 出发
- 9/30 出发
- 开罗 + 卢克索 + 赫尔格达
- 开罗 + 沙姆沙伊赫

切换后页面更新：

- 行程轴。
- 当前计入候选。
- 总价与评分。
- 不可行或待查段。

### 3. 中文行程轴

按日期显示每日安排：

- 日期和星期。
- 城市/景点/转场。
- 航班段以中文展示，如“北京 → 开罗”，小字显示“北京首都/大兴 BJS → 开罗 CAI”。
- 明确显示“直飞”“1 次中转”“未找到直飞”。
- 显示出发/到达时间、总耗时、航司、航班号、价格。
- 酒店和当地项目也放到对应日期下，而不是只在表格里。

### 4. 候选抽屉

每个行程段可以展开候选：

- 当前计入候选。
- 其他候选。
- 候选之间的价格差、耗时差、中转差。
- 打开来源。
- 修改价格、切换计入、添加备注。

### 5. 风险和待查清单

独立区域列出：

- 未找到直飞的航段。
- 没有实际候选的必需段。
- 托运行李待确认。
- 酒店餐食/房型待确认。
- 价格低置信度。
- 查询时间过旧。

## 中文化要求

页面主体必须使用中文可读名称：

- `BJS` 显示为“北京”。
- `LHW` 显示为“兰州中川”。
- `CGQ` 显示为“长春龙嘉”。
- `CAI` 显示为“开罗”。
- `LXR` 显示为“卢克索”。
- `HRG` 显示为“赫尔格达”。
- `SSH` 显示为“沙姆沙伊赫”。

机场代码只放在小字、徽标或 tooltip 中。

## 计算逻辑

只对“可行且已查到候选”的情景评分。

价格：

```text
scenario_total_cny = selected_flights + selected_hotels + selected_activities + selected_ground_transport
```

时间：

```text
scenario_travel_minutes = selected_flights.duration_minutes + selected_ground_transport.duration_minutes
```

评分：

```text
price_score = min(scenario_total_cny) / scenario_total_cny * 100
time_score = min(scenario_travel_minutes) / scenario_travel_minutes * 100
total_score = 0.5 * price_score + 0.5 * time_score
```

不可行情景不参与第一名推荐，但仍展示缺口。

## 搜索工作流

在更新数据前，必须优先搜索这些关键段：

1. 2026-09-29 北京 → 开罗。
2. 2026-09-30 北京 → 开罗。
3. 2026-10-06 开罗 → 北京。
4. 2026-10-06 或 2026-10-05 赫尔格达/沙姆沙伊赫 → 开罗衔接段。
5. 开罗 → 卢克索。
6. 卢克索 → 赫尔格达交通。
7. 开罗 ↔ 沙姆沙伊赫。

优先来源：

- 中国 OTA：携程、去哪儿、飞猪、美团。
- 国际补充：Trip.com、Skyscanner、Google Flights、航司官网、Booking、GetYourGuide、Viator。

若平台无法公开展示完整结果，数据中写明“待人工确认”，不能伪造成已查到结果。

## 验收标准

1. 页面第一屏能用中文说明当前推荐方案。
2. 页面不再把机场代码作为主要路线标题。
3. 10/6 开罗 → 北京如果没有直飞，必须显示“未找到直飞”。
4. 每个计入总价的航班候选必须有具体出发/到达时间、是否直飞、价格和来源。
5. 可以切换 9/29 与 9/30 出发情景。
6. 切换情景后，总价、移动时间、行程轴和风险清单同步变化。
7. 没有实际候选的必需段显示为“待查询”，不参与推荐评分。
8. 修改候选价格后，结论和总价即时更新。
9. 测试覆盖中文机场映射、无占位候选过滤、情景切换重算、未找到直飞提示。
